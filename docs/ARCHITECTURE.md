# Flowboard Architecture

This document is a concise overview for new contributors.

## High-level shape

Flowboard is a **pipe-and-filter workflow engine** specialized for the
Rheinmetall OnboardAPI ecosystem. The runtime loads a JSON graph definition,
instantiates nodes from a registry, wires them with type-checked edges, and
runs them on per-node worker threads.

```
+----------------------+    +----------------------+    +----------------------+
|  M_Mount.Client      | -->|  Transform.Threshold | -->|  M_Alert.Client      |
|  (OnboardAPI Client) |    |  (business logic)    |    |  (OnboardAPI Client) |
+----------------------+    +----------------------+    +----------------------+
        |                              |                            |
        | std::shared_ptr<const T>    edges = SPSC rings           |
        | pumped through per-edge jthreads                         |
```

## Three families of nodes

1. **OnboardAPI Service / Client nodes** — pure pass-throughs around the
   `M_<Interface>::Service` / `M_<Interface>::Client` SDK handles. Generated by
   `pipegen` from `.rmodel` files. 52 interfaces × 2 = 104 node types, plus
   304 `Factory.M_<X>::<Struct>` struct-builder nodes.

2. **Transform nodes** — Threshold, Compare, Map, Filter, Throttle, ConstantSource,
   Combine. Where the workflow logic lives. Hand-written.

3. **Sinks** — Log (writes to stdout / log file). The web UI's live-value pane is
   also a sink (via WebSocket).

## Engine primitives

| Type | Lives in | Role |
|---|---|---|
| `Port<T>` | `include/flowboard/port.hpp` | Typed endpoint with `type_tag()` for runtime validation. |
| `Edge<T>` | `include/flowboard/edge.hpp` | Lock-free SPSC ring (rigtorp). Two policies: `Block`, `DropOldest`. |
| `Node`    | `include/flowboard/node.hpp` | Base class. Owns a `std::jthread` worker; tasks land in a queue protected by a `std::counting_semaphore`. |
| `Graph`   | `include/flowboard/graph.hpp` | Owns nodes + edges. `connect()` validates type tags. `start()` / `stop()` lifecycle. Each edge gets its own pump `jthread` that drains the SPSC ring. |
| `NodeRegistry` | `include/flowboard/registry.hpp` | Map from string type name → factory. Self-registration via `OP_REGISTER_NODE`. |
| `GraphHolder` | `include/flowboard/graph_holder.hpp` | Owns the live graph + a mutex. The control plane swaps graphs atomically here. |

## Codegen — pipegen

Pipegen is a separate C++20 executable that parses `.rmodel` files (CORBA-IDL
subset) and emits four artifacts per module:

- `<module>_types.hpp` — struct definitions + `OP_DECLARE_TYPE` registrations + `to_json` per struct.
- `<module>_nodes.cpp` — generated `Service` / `Client` Node classes inheriting `IClient` / `IService`.
- `<module>_stub.hpp` — stub SDK headers (struct types + virtual interface shells). Consumed by `sdk_stub/`.
- `<module>_types.ts` — TypeScript catalog metadata for the web UI.

Plus a single `registry_init.cpp` that's the CMake sentinel.

## Stub SDK

`sdk_stub/` mimics the public ABI of the real OnboardAPI SDK enough that codegen
output compiles without the proprietary binaries. Semantics: in-process pub/sub
keyed by `(domainId, serviceName, opName)`. No DDS, no networking.

The stub headers are themselves generated from the OnboardAPI data model, which
is sourced from the `Rheinmetall/onboardapi` git submodule at
`external/onboardapi/datamodel` (pinned to tag v9.9.0). New interfaces come from
updating that submodule rather than editing in-tree copies.

## Control plane

A Crow-based HTTP+WebSocket server listening on `127.0.0.1:8765` by default. See
[README](../README.md) for the API surface.

## Web UI

`web/` is a Vite + React + TypeScript app using React Flow + Zustand + Tailwind.
Built at compile time, the `dist/` folder is embedded into the binary via
`cmake/EmbedWebAssets.cmake`.

## Lifecycle

1. `main.cpp` parses argv, loads the JSON config.
2. `config::load(doc)` validates + builds a `Graph` via `NodeRegistry`.
3. `GraphHolder::install()` attaches live taps + starts the graph (which starts
   per-node workers + per-edge pump jthreads).
4. `control::Server::start()` exposes the REST + WS API and serves the web UI.
5. Ctrl-C → signal handler sets a stop flag → server stops, holder stops, exit.

## File layout (condensed)

```
include/flowboard/     — public engine API
src/engine/               — engine impl
src/nodes/                — transform + sink nodes
src/config/               — JSON loader + schema
src/control/              — Crow server + routes
src/onboardapi/runtime/   — Service/Client node base classes (Phase 2+)
pipegen/                  — codegen tool
sdk_stub/                 — in-tree stub OnboardAPI SDK + rmodels
web/                      — React UI
docs/                     — this file + ADRs + per-feature guides
```
